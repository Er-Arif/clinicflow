# Android production configuration

The checked-in `mobile/android` project is authoritative for Android manifest, native dependencies, signing, and build configuration. Release identity metadata is duplicated intentionally in Expo/package metadata for runtime display; CI runs `npm run validate:release-metadata` and fails if `package.json`, `app.json`, and native Gradle disagree on the app version, Android version code, or package name.

Production API configuration is an explicit `EXPO_PUBLIC_API_URL=https://api.example.com` origin supplied to the Gradle/Metro build environment. No fallback address exists. Credentials, paths, query strings and fragments are rejected. Both ordinary API requests and refresh use the same validated origin. Production JS rejects HTTP regardless of `EXPO_PUBLIC_ALLOW_HTTP`; the main Android manifest also denies cleartext.

Local LAN/emulator testing remains available only in a debug build with an explicit API URL and `EXPO_PUBLIC_ALLOW_HTTP=true`. Debug/debugOptimized manifest overlays retain their cleartext permission. Previously built debug-signed release UAT artifacts are not production artifacts. Update local ignored `.env` explicitly if continuing HTTP debug UAT.

Provide these environment variables from user-owned signing material or a CI secret store:

- `CLINICFLOW_ANDROID_KEYSTORE`: absolute path outside the repository
- `CLINICFLOW_ANDROID_STORE_PASSWORD`
- `CLINICFLOW_ANDROID_KEY_ALIAS`
- `CLINICFLOW_ANDROID_KEY_PASSWORD`

Release uses only `signingConfigs.release`. `validateProductionRelease` checks the HTTPS origin, keystore, private-key alias and certificate, rejects debug signing, and runs before release preparation/bundling. Missing credentials fail closed; debug remains independently signed with the development key. No production key is generated by this repository.

Preparation: `cd mobile`, `npm ci`, then run lint, typecheck, `npm run validate:release-metadata`, and tests. To validate supplied signing/configuration without creating an APK/AAB, from `mobile/android`, run `.\gradlew.bat :app:validateProductionRelease` on Windows or `./gradlew :app:validateProductionRelease` on POSIX. A future authorized release may run `:app:assembleRelease` for the distributable APK. Do not skip validation tasks or override release signing. Verify the final artifact certificate and merged manifest as part of that release gate.

Every APK intended to replace an installed ClinicFlow build must increment Android `versionCode`. The GitHub Release asset URL and SHA-256 are then published through the backend update-policy metadata. The mobile app treats versionCode as authoritative for install ordering and uses the semantic version as display/release metadata. Keep the same application ID (`com.clinicflow.app`) and the same production signing key for the lifetime of the install lineage.

The in-app installer requires Android's user-controlled unknown-source flow. ClinicFlow must never silently install an APK. The eventual installer must download only the backend-advertised GitHub Release APK, verify the complete SHA-256 before launching Android's package installer, and leave final installation approval to the operating system/user.

Native Gradle resolves Android artifacts independently from npm/uv; this pass does not certify bit-for-bit Android builds or introduce native dependency locking. Build hosts must provide the required Android SDK/NDK/JDK toolchain outside the repository. On Windows, native intermediates default to the generic short path `C:/cxx` to avoid path-length failures and may be overridden with `CLINICFLOW_ANDROID_CXX_DIR`; `local.properties` remains ignored. No EAS signing profile is configured; native Gradle is the documented release path.

Before rollout, confirm HTTPS/certificate validation, rejected cleartext, login/refresh/recovery, proxy throttling, update-policy behavior, and the existing keyboard-safe forms on a physical device. Archive the artifact hash, signing certificate fingerprint, versions and commit using the release artifact policy. Keep signing recovery material separate from the repository and artifact archive.
